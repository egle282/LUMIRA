## 🛠 Инструкция для AI (Shutdown Protocol)

При получении команды на выполнение этого файла, я обязан выполнить следующие шаги:

### 1. 🧠 Content & UI Logic

Убедиться, что логика работы с контентом и UI корректно настроена:

- **Domain Structure**: Бэкенд и фронтенд компоненты корректно распределены.
- **AI Integration**: Оркестратор и ИИ-модели правильно интегрированы и маршрутизация работает.
- **Core Engine**: Движок Swiss Ephemeris корректно возвращает данные.
- **UI Components**: Все компоненты приложения (MyChart, Dashboard, Auth) работают корректно.

### 2. 🧠 Session Analysis & Knowledge Retention (Анализ и Сохранение Опыта)

- [x] **Анализ текущей сессии**: Провести ретроспективу решенных задач, выявленных багов и архитектурных решений.
- [x] **Пополнение базы знаний**: Добавить полученный опыт, инсайты и описания решенных проблем в файл `.antigravity/EXPERIENCE.md`, чтобы предотвратить их повторение в будущем.
- [x] **Покрытие тестами (Regression Prevention)**: Написать автоматизированные тесты для всех проблемных мест и багов, исправленных в текущей сессии, чтобы гарантировать, что они не возникнут снова при будущих изменениях кода.

### 3. 📂 Documentation Sync (Синхронизация Документации)

- [x] **Обновить README.md**: Добавить описание новых функций, изменившихся маршрутов или структуры.
- [x] **Обновить PROJECT_STATUS.md**: Зафиксировать стратегические изменения в архитектуре и текущую версию проекта.
- [x] **Обновить PROJECT DUMP.txt**: Запустить генерацию `project_dump.py`, чтобы создать свежий слепок исходного кода.
- [x] **Актуализировать .antigravity/.planning**: Проверить и при необходимости обновить планы, чтобы они соответствовали текущему состоянию проекта.
- [x] **Прямая фиксация истории в Obsidian & NotebookLM (НЕ в session_sync.md)**: Лог сессии НЕ пишется в `session_sync.md`. Все резюме релиза и сессии записываются строго напрямую в Obsidian Vault (`01_Projects/LUMIRA/sessions/`) и NotebookLM.
- [x] **Синхронизация с NotebookLM**: По завершении сессии выгрузить свежий слепок исходного кода (`project_dump.txt`) и обновленную документацию в блокнот `LUMIRA`.
- [x] **Обновить контекст**: Запустить актуализацию сведений о структуре, тестах и окружении проекта.

### 4. 🧠 Content Validation (Валидация Контента)

- [x] **API Validation**: Проверить эндпоинты FastAPI на правильность работы.
- [x] **Database Structure**: Убедиться, что все новые таблицы/модели SQLAlchemy мигрированы.
- [x] **Environment**: Проверить корректность переменных окружения (.env).

### 5. 🛡️ Verification & Safety

- [x] **Build Check**: Запустить `npm run build` во фронтенде и перезапустить бэкенд для проверки отсутствия ошибок.
- [x] **Lint Check**: Проверить код на соответствие стандартам.
- [x] **Commit**: Подготовить Conventional Commit для всех изменений.

### 6. 📝 Mandatory Handoff Report (Обязательный финальный отчет)

По завершении протокола, AI-ассистент обязан вывести подробный финальный статус в своем ответе:

- **Что успешно синхронизировано** (Код, README.md, Документация, Локальный дамп, Git-ветка).
- **Что не удалось синхронизировать/обновить** из-за внешних ограничений.
- **Инструкции к действию для пользователя** по несинхронизированным элементам.
